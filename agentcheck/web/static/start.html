How a call is judged

Not a score. A decision, with the reasoning that produced it, persisted so you can still answer "what did we tell you to do?" months later.

  1. Decompose the call into atomic questions. Batch them. One round trip.
  2. Correct the confidence against measured accuracy. A 0.9 from a judge that is right 70% of the time reads as what it is.
  3. Floor it. Deterministic screens only ever downgrade pass → review. Worst case is one more human look.
  4. Decide: approve, human, or block, using a policy you wrote.

Bring your own judge

Any OpenAI-compatible key via OPENAI_API_KEY / OPENAI_BASE_URL, so OpenAI, OpenRouter, vLLM and Ollama all work. Or a TypeSafe key. Or nothing: an offline stub keeps every feature runnable, and the UI says so.

Swap judges by writing one adapter file. Every calibration report names the judge that measured it, so switching vendors is a cost, not a rewrite.

Why not just a keyword filter? Same 467 attacks: ~75% ASR against literals, 3.2% against a judge with screens. And when a regex really is the right answer.
